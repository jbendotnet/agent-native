# 組織、團隊與權限

組織定義團隊成員和租戶界線。工作區彙整應用程式與部署設定，但不會取代組織。權限必須由伺服器檢查。在介面隱藏按鈕並不等於存取控制。

## 三種角色範圍

- 組織角色 `owner`、`admin` 和 `member` 控制團隊管理。擁有者和管理員管理電子郵件網域自動加入；應用程式之間共用的 A2A 密鑰只有擁有者可以管理。
- 應用程式角色控制單一應用程式內的操作。一位成員可以有多個應用程式角色。
- 資源角色 `viewer`、`editor` 和 `admin` 控制單筆資料的存取。

應用程式程式碼宣告角色和權限鍵。管理員可在團隊頁面取代成員的整組角色，並將已宣告的權限對應到角色。沒有覆寫時採用應用程式預設值。邀請可以預先包含應用程式角色。應用程式管理員不會因此取得組織管理權限。

邀請和設定請參閱[管理式部署指南](/docs/administered-deployments)。資料存取請參閱[資料範圍控制](/docs/security#data-scoping)。

## 可選權限政策

預設情況下，權限檢查要求已指派的應用程式角色。透過 `defineAppRoles` 的可選第二個參數，可以變更伺服器端政策。Forms 使用：

```ts
const formsAccess = defineAppRoles(
  {
    appId: "forms",
    roles: ["editor", "reviewer"] as const,
    defaultRole: "editor",
    permissions: {
      "forms.edit": ["editor"],
      "forms.review": ["editor", "reviewer"],
    },
  },
  { unassignedRole: "editor", allowOrgAdmins: true },
);
```

- `unassignedRole` 將已宣告角色的權限套用至沒有應用程式角色指派的有效成員。權限覆寫仍然生效。它不會建立角色指派，也不適用於已移除的成員或僅包含已廢棄角色的指派。清除全部指派後，會恢復此預設行為。
- `allowOrgAdmins: true` 允許組織的有效擁有者和管理員通過任何已宣告的應用程式權限檢查，不受其應用程式角色或權限覆寫影響。它不會向應用程式管理員授予組織管理權限。

這些選項僅影響 `requirePermission` 和 `assertPermission`。`resolve`、`requireAny` 和 `assertAny` 仍使用明確指派；`defaultRole` 仍僅用於顯示。省略選項時保留嚴格政策。兩者都不取代資源授權：請保留 `accessFilter` 和 `assertAccess` 檢查。

Forms 保留現有未指派角色成員的編輯權限。明確指派的 Reviewer 可以審查提交內容，但不能編輯表單；Editor 可以執行兩種操作。資源分享仍決定他們能存取哪些表單和提交內容。

編輯組織所屬的表單或審查其提交內容，要求呼叫者是該表單所在組織的有效成員，除非分享系統將呼叫者識別為表單擁有者。僅有直接分享權限並不足以通過此應用程式權限檢查。

## 使用者群組 {#user-groups}

組織可以建立由目前成員組成的可重複使用使用者群組。擁有者和管理員負責管理群組成員，同一個人可以加入多個群組。應用程式可以使用群組來分享支援群組分享的資源，或限制可使用工作區連線的人員。

一般群組是存取名單。只有明確設定 `isTeam: true` 才會將其轉換為團隊。轉換保留 ID、成員以及資源和連線授權。更新時省略 `isTeam` 會保留現有類型。組織擁有者和管理員可建立、轉換、重新命名和刪除團隊，以及指定負責人。負責人只能管理自己團隊的一般成員，不會取得組織角色或私人對話存取權。

### 團隊脈絡與對話綁定 {#team-context}

選擇按使用者和組織儲存。`get-active-workspace-team` 還原並驗證選擇。`set-active-workspace-team` 選擇目前團隊，或用 `null` 選擇個人工作。這只影響新對話。現有對話的綁定不可變，舊的未綁定對話仍未綁定。選擇團隊不會授予存取權或分享對話。

V1 只支援團隊指示、技能和記憶，不支援團隊擁有任意應用程式資料。資源使用 `scope: "team"` 和 `teamGroupId`。前景和背景執行在組織脈絡之後、個人脈絡之前載入綁定團隊的脈絡。刪除團隊會保留綁定對話、脈絡、個人資源和分享記錄，但終止透過該團隊的存取。同名新團隊會取得新的 ID。

### 團隊操作 {#team-actions}

| 操作                                | 輸入                                                      | 回傳值                                                                                             |
| ----------------------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `upsert-workspace-user-group`       | `{ id?, name, memberEmails?: [], isTeam?, leadEmails? }`  | 含 `id`、`orgId`、`name`、`memberEmails`、`isTeam`、`leadEmails` 和中繼資料的群組。成員預設為 `[]` |
| `set-workspace-team-leads`          | `{ teamGroupId, leadEmails }`                             | 更新後的群組。取代完整負責人清單                                                                   |
| `bulk-update-workspace-user-groups` | `{ groupId, memberEmails, operation: "add" \| "remove" }` | 更新後的群組。1 至 100 個電子郵件地址                                                              |
| `list-workspace-user-groups`        | `{}`                                                      | 群組。僅擁有者、管理員及該團隊成員可查看成員和負責人清單                                           |
| `delete-workspace-user-group`       | `{ id }`                                                  | `{ id, deleted: true }`。不存在時失敗                                                              |
| `set-active-workspace-team`         | `{ teamGroupId: string \| null }`                         | 驗證成員資格後回傳 `{ orgId, teamGroupId }`                                                        |
| `get-active-workspace-team`         | `{}`                                                      | `{ orgId, teamGroupId }`，並將選擇還原至應用程式狀態                                               |

擁有者或管理員可以建立團隊，但必須也是團隊成員才能選擇它：

```ts
import { callAction } from "@agent-native/core/client/hooks";

await callAction("upsert-workspace-user-group", {
  name: "Support",
  isTeam: true,
  memberEmails: ["lead@example.com", "member@example.com"],
  leadEmails: ["lead@example.com"],
});
```

轉換現有群組時須明確保留成員。之後可切回個人工作：

```ts
const groups = await callAction("list-workspace-user-groups", {});
const group = groups.find((group) => group.name === "Support");
if (!group) throw new Error("找不到 Support 群組");

await callAction("upsert-workspace-user-group", {
  id: group.id,
  name: group.name,
  memberEmails: group.memberEmails,
  isTeam: true,
});
await callAction("set-active-workspace-team", { teamGroupId: null });
```

對話仍由個人擁有，預設保持私密。唯讀分享規則見[團隊對話](/docs/sharing#team-conversations)。

詳情請參閱[分享與隱私 → 群組分享](/docs/sharing#group-grants)和[工作區連線](/docs/workspace-connections)。
