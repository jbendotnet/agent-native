# المؤسسات والفرق والأذونات

تحدد المؤسسة عضوية الفريق وحدود المستأجر. تجمع مساحة العمل التطبيقات وإعدادات النشر لكنها لا تستبدل المؤسسة. يجب أن يتحقق الخادم من الصلاحية. إخفاء زر في الواجهة ليس تفويضاً.

## نطاقات الأدوار الثلاثة

- أدوار المؤسسة `owner` و`admin` و`member` تتحكم بإدارة الفريق. يدير المالكون والمسؤولون الانضمام التلقائي حسب نطاق البريد الإلكتروني، ويدير المالك وحده سر A2A المشترك بين التطبيقات.
- أدوار التطبيق تتحكم بما يمكن فعله داخل تطبيق واحد. يمكن للعضو امتلاك عدة أدوار.
- أدوار المورد `viewer` و`editor` و`admin` تتحكم بالوصول إلى سجل واحد.

يعرّف التطبيق الأدوار ومفاتيح الأذونات في الشيفرة. يستطيع المسؤول استبدال مجموعة أدوار العضو وربط الأذونات المعرّفة بالأدوار من صفحة الفريق. عند غياب التخصيص تسري القيم الافتراضية للتطبيق. يمكن أن تتضمن الدعوة أدوار تطبيق مسبقة. دور مسؤول التطبيق لا يمنح صلاحيات إدارة المؤسسة.

للدعوات المُدارة راجع [عمليات النشر المُدارة](/docs/administered-deployments). وللوصول إلى البيانات راجع [نطاق البيانات](/docs/security#data-scoping).

## مجموعات المستخدمين {#user-groups}

يمكن أن تضم المؤسسة مجموعات مستخدمين قابلة لإعادة الاستخدام من أعضائها الحاليين. يدير المالكون والمسؤولون العضوية، ويمكن للشخص الانتماء إلى أكثر من مجموعة. يمكن للتطبيقات استخدام المجموعة لمشاركة مورد يدعم مشاركة المجموعات أو لتقييد الوصول إلى اتصال مساحة العمل.

المجموعة الجديدة قائمة وصول عادية. لتحويلها إلى فريق، يجب تمرير `isTeam: true` صراحةً إلى `upsert-workspace-user-group`. يحافظ تحويل مجموعة موجودة على معرّفها وأعضائها ومنح وصول الموارد والاتصالات. لا يغيّر حذف `isTeam` من مدخلات التحديث نوع المجموعة. لا تملك المجموعة العادية سياق فريق أو اكتشافًا لمحادثاته المشتركة.

ينشئ مالكو المؤسسة ومسؤولوها الفرق ويحوّلون المجموعات ويعيدون تسميتها ويحذفونها ويعيّنون قادتها. يستطيع القائد إضافة أعضاء عاديين إلى فريقه أو إزالتهم فقط. لا يستطيع تعديل القادة أو أدوار المؤسسة. لا يمنح دور الفريق وصولًا إلى محادثات الآخرين الخاصة.

### سياق الفريق {#team-context}

يُحفظ الفريق النشط لكل مستخدم ومؤسسة على حدة. يستعيد `get-active-workspace-team` الاختيار ويتحقق مجددًا من العضوية. يختار `set-active-workspace-team` السياق الشخصي عند تمرير `teamGroupId: null`. ينطبق الاختيار على المحادثات الجديدة فقط. لا يتغيّر ارتباط المحادثات الموجودة بفريقها، وتبقى المحادثات القديمة غير المرتبطة كما هي. الاختيار ليس منحة وصول.

يدعم V1 تعليمات الفريق ومهاراته وذاكرته، لا ملكية الفريق لبيانات التطبيق العامة. تتطلب موارد الفريق `scope: "team"` و`teamGroupId`. تحمّل عمليات التشغيل العادية والخلفية سياق الفريق المرتبط بالمحادثة بعد سياق المؤسسة وقبل السياق الشخصي.

يحتفظ حذف الفريق بالمحادثات المرتبطة والسياق والموارد الشخصية وسجلات المشاركة، لكنه يمنع الوصول اللاحق. يحصل الفريق الجديد الذي يحمل الاسم نفسه على معرّف جديد، ولا يرث البيانات القديمة.

### إجراءات الفريق {#team-actions}

| الإجراء                             | المدخلات                                                                | النتيجة                                                                                     |
| ----------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `upsert-workspace-user-group`       | `id?`, `name`, `memberEmails?: string[] = []`, `isTeam?`, `leadEmails?` | المجموعة مع `id`, `orgId`, `name`, `memberEmails`, `isTeam`, `leadEmails` والبيانات الوصفية |
| `set-workspace-team-leads`          | `teamGroupId` وقائمة `leadEmails` الكاملة                               | المجموعة المحدّثة                                                                           |
| `bulk-update-workspace-user-groups` | `groupId` ومن 1 إلى 100 `memberEmails` و`operation: "add" \| "remove"`  | المجموعة المحدّثة                                                                           |
| `list-workspace-user-groups`        | `{}`                                                                    | المجموعات. يتلقى غير المسؤول قوائم أعضاء وقادة فارغة باستثناء الفرق التي ينتمي إليها        |
| `delete-workspace-user-group`       | `id`                                                                    | `{ id, deleted: true }`، أو خطأ إذا لم توجد المجموعة                                        |
| `set-active-workspace-team`         | `teamGroupId: string \| null`                                           | `{ orgId, teamGroupId }`                                                                    |
| `get-active-workspace-team`         | `{}`                                                                    | `{ orgId, teamGroupId }`                                                                    |

يستطيع المالك أو المسؤول إنشاء فريق. ويجب أن يكون المستدعي عضوًا فيه أيضًا لاختياره. تُستبدل عناوين المثال بأعضاء موجودين في المؤسسة.

```ts
import { callAction } from "@agent-native/core/client/hooks";

await callAction("upsert-workspace-user-group", {
  name: "Support",
  memberEmails: ["lead@example.com", "member@example.com"],
  isTeam: true,
  leadEmails: ["lead@example.com"],
});
```

عند تحويل مجموعة موجودة، تُمرر قائمة أعضائها الحالية. القيمة الافتراضية لـ`memberEmails` عند حذفها قائمة فارغة. يمكن للمستدعي بعدها اختيار السياق الشخصي.

```ts
const groups = await callAction("list-workspace-user-groups", {});
const group = groups.find((group) => group.name === "Support");
if (!group) throw new Error("لم يتم العثور على مجموعة Support");

await callAction("upsert-workspace-user-group", {
  id: group.id,
  name: group.name,
  memberEmails: group.memberEmails,
  isTeam: true,
});
await callAction("set-active-workspace-team", { teamGroupId: null });
```

المحادثات خاصة افتراضيًا، ومشاركة الفريق للعرض فقط. راجع [محادثات الفريق](/docs/sharing#team-conversations).

راجع [المشاركة والخصوصية → مشاركة المجموعات](/docs/sharing#group-grants) و[اتصالات مساحة العمل](/docs/workspace-connections) لمعرفة التفاصيل.
