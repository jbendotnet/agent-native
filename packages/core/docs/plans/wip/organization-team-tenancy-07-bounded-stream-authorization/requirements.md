# Epic 7 requirements

Source: the [proposed tenancy amendment](https://github.com/jbendotnet/agent-native/blob/ea1df2b21d94f49441649d9c520b155a72feb2f8/packages/core/docs/design/organization-team-tenancy.md#proposed-stream-policy-amendment-2026-10-10), [shared lease contract](https://github.com/jbendotnet/agent-native/blob/ea1df2b21d94f49441649d9c520b155a72feb2f8/packages/core/docs/design/durable-agent-runs.md#bounded-viewer-authorization-leases), and [review request](https://github.com/BuilderIO/agent-native/pull/5777#issuecomment-6081437360). These requirements supplement the completed Epics 1–6 baseline.

| ID   | Requirement                                                                                                                                                                                                                                                                                           | Acceptance evidence                                                                                                                                                                                                                                         |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| S-01 | Record approval of the stream amendment, lease duration, renewal interval, disclosure window, and fail-closed behavior. The proposed 10s/5s values are not approved by this plan.                                                                                                                     | Recorded policy decision reflected in both design documents.                                                                                                                                                                                                |
| S-02 | Every authorized subscription uses a fresh, coherent authoritative decision for its original viewer and applicable access policy. Missing linked conversations deny access. Preserve genuine standalone and supported public policies.                                                                | Policy/identity matrix, current org/team/share checks, missing linked target, and retained alternative access.                                                                                                                                              |
| S-03 | Enforce absolute monotonic deadlines from check start, one in-flight check, and terminal closure. Gate every final application-controlled write across live, SQL-polled, replayed, buffered, and keepalive delivery. Denial/error closes immediately. Timeout or delayed timers never extends access. | Successful renewal and initial authorization, slow pre-commit approval, late approval after expiry, backend failure/timeout, delayed timers, and backpressure. Measure the approved bound after committed revocation at the final writer, not only enqueue. |
| S-04 | Subscription closure never cancels or completes its producer. Reconnect authorizes afresh before replay. Preserve existing data, access rights, owner/viewer separation, and unrelated tenancy behavior.                                                                                              | Independent open-stream org/team removal, team deletion, share and applicable identity revocation, non-team/standalone/public compatibility, client closure/reconnect, and producer continuity proof against the final stack.                               |
| S-05 | Record query cost, independent evidence, actual release documentation, configured translations, and required package changesets. Publish and link the owning follow-up in the PR discussion before reporting the review request fully addressed.                                                      | Representative authorization-load measurements, commands/results and delivery-path matrix, docs/locales/changeset diff, published follow-up URL, and honest release handoff.                                                                                |

The bound covers new application-controlled writes after committed access revocation. It does not limit byte volume or recall transport bytes already written. Design approval is not runtime proof. Completing Epics 1–6 does not satisfy these gates or authorize amended V1 release.

No routine commit, push, PR creation, merge, or deployment permission is implied by this plan. Do not move or reopen completed epics merely to add this follow-up.
