# Epic 5 requirements

Source: [accepted ADR](../../../design/organization-team-tenancy.md).

| ID   | Requirement                                                                                                                                                                                                                                                                                                                           | Acceptance evidence                                                                                 |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| H-01 | Add `share-chat-thread-with-team` and `unshare-chat-thread-from-team`, taking thread/team IDs and returning share state. Require recorded owner/current org and target-team membership; marked team matches thread org; bound thread targets only bound team; viewer only; one explicit team grant maximum; preserve non-team shares. | Owner/role/team matrix, concurrent recipient attempts, generic bypass rejection.                    |
| H-02 | Add paginated `list-team-shared-chat-threads(teamGroupId, pagination)`. Current org/team member required; only explicit shares returned. Direct/list/cache checks revalidate current access. Binding alone grants nothing.                                                                                                            | Private bound exclusion, pagination, revoked grant/removal/deletion, viewer cannot continue/manage. |
| H-03 | Shared UI grants/revokes using the same actions, shows authorized shared conversations and linked runs through existing run helpers, and remains read-only for team viewers.                                                                                                                                                          | Browser/action parity; no admin/lead private read exception.                                        |

Unbound team sharing changes neither ownership nor context nor existing public-token behavior. Existing supported resource families can reuse the marked group grant without ownership moves; unsupported/unknown resource types do not gain access.
